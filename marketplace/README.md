# Parser pack publishing

The official marketplace is owner-published. Add validated YAML and fixtures, then update `metadata.json`. Use `packs` metadata for vendor/product/model coverage and `releases` entries keyed by `pack-name@version` for changelog, `withdrawn`, `min_worm`, `required_decoders`, and RFC3339 `published_at` values. Required decoder names currently match the supported parser families: `syslog`, `json`, `csv`, `cef`, `xml`, `leef`, and `text`.

A published `name@version` and its SHA-256 are immutable. Keep every prior YAML under `marketplace/releases/`; the publisher compares against the committed signed catalog and fails if a published version changes or disappears. The committed `internal/marketplace/catalog.json` is the binary seed catalog. Run the publisher with the owner-held signing key to regenerate it, review and commit the result with the pack changes, then let the protected `marketplace-publish` GitHub environment publish the static site. CI also verifies that shipped packs match the signed seed before publishing or building release archives.

Keep the Ed25519 private key in durable owner-controlled secret storage and configure the GitHub Actions secret `WORM_MARKETPLACE_SIGNING_KEY` with its base64 encoding. The current owner key ID is `worm-market-2026-v2`; WORM retains the previous `worm-market-2026` public key so older signed catalogs remain verifiable. Never put the private key in Git or expose it to pull-request workflows. Customers need a WORM build that trusts a signing key before they can refresh a catalog signed with it.
